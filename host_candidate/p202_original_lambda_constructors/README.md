# P202 — original Kotlin EngineManager.start caller *instantiation* provenance

P201 decoded the real exact signed v138 DEX and identified four `EngineManager.start()` instructions, in `MainActivity$autoEnterSafeMode$1.invokeSuspend`, `MainActivity$bootEngine$1.invokeSuspend`, `MainActivity$enterSafeMode$1.invokeSuspend`, and `MainActivity$observeEngine$1$1$1.invokeSuspend`. Each immediate inbound `invokeSuspend` method graph has limited direct information because Kotlin suspend-lambda objects are normally constructed/allocated outside their `invokeSuspend` bodies.

P202 reads **only** the original fixed SHA256 `3ca56655d79afc57431636e340823e7071bc830615ca615c485b0b9a30b6e3e5` Android APK, using pinned androguard 4.1.4, and examines the exact four original `MainActivity$` suspend class symbols and the original application `classes*.dex`. It counts `new-instance` allocation references separately from actual `invoke-direct Class.<init>` constructor references, and reports for each constructor call the **original containing method symbol**, bytecode PC, symbolic class role, method-event signature and bounded exact upstream method calls (up to 3 levels). It cross-checks the frozen P201 4/1/3 `EngineManager.start/probeBoot/runDumpConfig` direct sites and requires a unique `invokeSuspend` definition for each target class.

This is static evidence only; **construction does not prove a user click, Kotlin coroutine dispatch, Android system-owner generation, real Node start, or a working engine**. Missing constructor or allocation sites are reported as zero and UNKNOWN (never invented). Indirect invokes, interface dispatch, reflection and caller-side Kotlin coroutine scheduling may require further scope-specific examination. The auditor never prints original invoke arguments, Java string constants, launch command lines, paths, URLs, model outputs, cookies, IPs or tokens. All private APK bytes and ephemeral reports are deleted by the runner, not uploaded.
