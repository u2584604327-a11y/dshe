# P302: isolated Android35 Binder FD bounded stream and replay (synthetic only)

P301 at SHA 59fb2e06 and Actions 44327611563 already proved one 14-byte real Android35 reliable-pipe EOF success. P302 keeps P301 byte-exact and runs a separate com.dsh.p302probe disposable no-network app on fresh GitHub-hosted QEMU Android35 x86_64.

P302 host sends a deterministic 65,536-byte nonsecret synthetic byte sequence over a reliable ParcelFileDescriptor pipe to a non-exported isolatedProcess Service. The isolated receiver checks every byte in 4,096-byte reads, exact total length and clean reliable EOF. Host keeps its own reader FD open until the Binder reply; any failure is denied. After the positive receipt, host intentionally sends a second authenticated Binder request without an FD, and worker must reject replay with DENY_WORKER_REPLAY. A rejection marker counts as PASS only when paired with actual replay delivery and host receipt. Runner requires fixed one-shot markers; all other DENY, missing or duplicate markers, invalid emulator, or stale package fail.

P302 changes only this new synthetic folder and one new workflow. It makes NO changes to production original DSH, original P245/P192/P47/B3/B4 or permissions. No original ARM64 Node JS/module execution, no real original EngineManager/HTTP token READY, no phone, accounts or signing. The original isolated loopback BIND_EACCES is still blocked. Never publish the disposable APK as v139. Even P302 PASS only attests synthetic 65,536-byte FD delivery and replay denial, not original module resolution or account isolation.

## P307 nonperiodic bounded fixture

The previous `(i*31+7)&255` payload had a 256-byte period, which meant all 16 aligned 4,096-byte blocks were identical even if the receiver performed byte-for-byte checking. P307 changes only synthetic host and isolated worker fixture generation to `(i*31+7+(i>>>8)*17+(i>>>12)*53)&255`. For every block starting at `4096*b`, its first byte is `(7+69*b)&255`, so all 16 first bytes are distinct; full 4KiB blocks are distinct as well. An offline source-anchored check rejects reverting to the old formula or equal/reordered fixture blocks. The real Android35 test still requires actual total length, byte equality, reliable EOF, framework UID and replay rejection, with no original Node or release claim. Existing P301 14-byte success and P306 64KiB baseline remain separately immutable historical SHA results.
